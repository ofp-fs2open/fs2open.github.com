# Engine Features

Features that change what a mission or mod can do in the game. Many of them also add editor support, but they are listed here because the game uses them. See also [QtFRED Features](OFP-QtFRED-Features) and [Bug Fixes](OFP-Bug-Fixes).

| Feature | What it does | Commit |
|---|---|---|
| **Models for intel entries** | Lets intel (tech-room) entries display 3D models. | [79c8519](https://github.com/ofp-fs2open/fs2open.github.com/commit/79c85193a903a4caeab58566078dec4f1cd74e16) |
| **MP4 & OGG support for anims** | Video files are now a supported animation type in the UI | [1056720](https://github.com/ofp-fs2open/fs2open.github.com/commit/1056720c8da14e18966fe5c2b5d9fcdcbc65f706) |
| **APNGs support looping keyframes** | APNGs built with AnimStudio can have and fully support looping keyframes | [4cecacb](https://github.com/ofp-fs2open/fs2open.github.com/commit/4cecacb11c0184eeb194c9ce480112b47c090208) |
| **Coordinate Points Object Type** | New Coordinate Points objects are 2D rendered shapes that can be targeted by players | [6e394af](https://github.com/ofp-fs2open/fs2open.github.com/commit/6e394af2d469ce34725558281a6a72bbc53b185b) |
| **Props Feature Upgrades** | Props fully support texture replacement and spawn/despawn sexps | [d2753c1](https://github.com/ofp-fs2open/fs2open.github.com/commit/d2753c1f98e00649cf09add37bd5df7f5e3cfa44) |
| **Ship Instance Custom Data** | Individual ships carry named custom data values (e.g. `Bounty = 75`), set in qtFRED and read or changed during the mission by [SEXPs](OFP-SEXPs#ship-custom-data-operators) and [Lua](OFP-Lua-Scripting#ship-custom-data) | [aac4194](https://github.com/ofp-fs2open/fs2open.github.com/commit/aac4194d37093270aefd5f1792058a80340b462c) |
| **Ship Nameplates** | Each ship can carry its own name or hull marking on its hull, either as text the game draws (font, scale, letter spacing, color, offset and resolution) or as a texture file, set in QtFRED's Nameplate dialog with a live preview. Models opt in with a texture named `nameplate`; the `$nameplate_width` / `$nameplate_height` submodel properties set its default size (16 to 1024). Missions using it require 26.1; FSO Compatibility Mode saves texture nameplates as a plain texture replacement older builds read | [d79c8d2](https://github.com/ofp-fs2open/fs2open.github.com/commit/d79c8d28381107f577747d88b515fc49572dd86d) |
| **Generated Background Nebula** | FS1's background nebula is back as a modern generated backdrop: a soft cloud sphere behind the stars, picked per mission with the original +Nebula: / +Color: fields and turned on with a new +Generated Nebula: field (so older missions that only carry the FS1 fields are unchanged). Patterns and colors come from [generated_nebula.tbl](generated_nebula.tbl): procedural noise, placed clouds, or both; the built-in Nebula01-03 are laid out like the FS1 originals and the nine colors are FS1's exact palette colors. qtFRED's Background Editor shows it live. | [7c30471](https://github.com/ofp-fs2open/fs2open.github.com/commit/7c304715449df35f5f8987a611f716dadbe31b48) |
