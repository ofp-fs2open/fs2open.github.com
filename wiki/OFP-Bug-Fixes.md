# Bug Fixes

Fixes for bugs in code OFP shares with SCP, newest first. Fixes to OFP's own features are covered by those features. See also [Engine Features](OFP-Engine-Features) and [QtFRED Features](OFP-QtFRED-Features).

| Fix | What it fixes | Commit |
|---|---|---|
| **QtFRED Attack ship type initial order** | Opening Initial Orders on a ship with an ai-chase-ship-type order raised "Unhandled AI_GOAL_X #define 27", the error checker reported it as an invalid goal type, and the order couldn't be created in QtFRED at all (only the engine, FRED2 and saving had been updated). QtFRED now lists Attack ship type with a ship type target, loads and saves it, and checks it. | [4d55455](https://github.com/ofp-fs2open/fs2open.github.com/commit/4d5545532b7afcceac89c6edca40cab6ad06d17c) |
| **QtFRED Initial Status with several ships** | Clicking OK in the Initial Status editor with several ships selected could crash QtFRED. OK also overwrote the ships' own values: where they differed, velocity, hull and shields were set to 101, and every ship got the current ship's guardian threshold and team color. Values the ships don't share now show blank instead of "-" and are kept on OK, and a picked team color only goes to classes that use team colors. | [59362be](https://github.com/ofp-fs2open/fs2open.github.com/commit/59362be47e93667d6d1d5d809951a9649352d493) |
| **QtFRED Mission Goals editor reset goal names** | A goal added or renamed in the Mission Goals editor wasn't offered in goal-name dropdowns, and when another objective referred to it (such as with is-goal-true-delay), editing any other argument of that SEXP reset the name to the first saved goal. The editor now offers its unsaved goals, as the Events editor already did for events. | [1da4033](https://github.com/ofp-fs2open/fs2open.github.com/commit/1da40337dc3b1b5558c6c0de9eada0c17a5f8047) |
| **QtFRED selection groups overlapped** | QtFRED stored group N as the number N instead of one bit per group as FRED2 does, so selecting group 3 also picked up groups 1 and 2, and setting group 3 emptied them. A ship that had never been put in a group counted as a member of every group, and Set Group couldn't be undone. Each group is its own bit now, ungrouped ships are in none, and Set Group is undoable. | [4416752](https://github.com/ofp-fs2open/fs2open.github.com/commit/4416752f24c6accc9e035866b448043792539ae1) |
| **QtFRED unreadable text on colored annotation rows** | Rows given an annotation color in SEXP trees (such as the Events editor) kept the theme's text color, which could vanish on the background, like white text on yellow in the dark theme. The text now switches to a color that reads against the row. Comment-only annotations no longer turn their row white, and removing a color clears it. | [e8aec0e](https://github.com/ofp-fs2open/fs2open.github.com/commit/e8aec0e79308b72a78294c60332f3a8ad1345cdc) |
| **QtFRED minimized by warning dialogs** | Every warning or error dialog (such as a model warning while loading) minimized the whole QtFRED window. The dialog now just appears on top of the editor. | [55ffab2](https://github.com/ofp-fs2open/fs2open.github.com/commit/55ffab259eb78efbfdf7de23aa4439085d29e4a9) |
| **QtFRED crash on close in Lua shutdown** | Closing QtFRED could crash with an access violation while shutting down Lua: QtFRED never closed the script system itself, so it was closed during program exit, after data its cleanup needed could already be gone. QtFRED now closes it during shutdown, as the game does. | [de9b2f3](https://github.com/ofp-fs2open/fs2open.github.com/commit/de9b2f3b3a4a054c25a3c56cb58f8f55b69c807f) |
| **QtFRED Lock Marked Objects could be bypassed** | Objects made unselectable with Edit > Lock Marked Objects (now Select > Lock Marked Objects) could still be marked by Select All in the Scene Browser, group selection, Mark Wing and next/previous object, and then moved with a drag. Marking and selecting now skip them. | [a07db54](https://github.com/ofp-fs2open/fs2open.github.com/commit/a07db546e61484f92a04ad39ff196a805e373d3d) |
| **QtFRED transform toolbar changed all three axes** | Editing one transform toolbar box (X, Y or Z, or heading, pitch or bank) wrote all three boxes to every marked object, so lining several ships up on one Y also gave them the same X and Z, and the boxes' one-decimal rounding nudged the axes nobody touched. Clicking into a box and back out also moved the selection. Only the edited axis changes now, only when a value is typed, and the boxes show two decimals. | [09aeb25](https://github.com/ofp-fs2open/fs2open.github.com/commit/09aeb25347b6bd2bc810ae37fe8f1950782e6133) |
| **QtFRED toolbar boxes stayed highlighted** | Text selected in a transform toolbar box (or the FOV box) stayed highlighted after clicking into the viewport, even when the box changed or was disabled, so two boxes could look focused at once. | [09aeb25](https://github.com/ofp-fs2open/fs2open.github.com/commit/09aeb25347b6bd2bc810ae37fe8f1950782e6133) |
| **Editors ignored Unified Scanning Behavior for subsystem scanning** | With `$Unify scanning behavior` on, a capital ship flagged `toggle-subsystem-scanning` was missing from the ship list for `cap-subsys-cargo-known-delay`, though its subsystems scan in game; the editors still used the classic rule, where the flag inverts the capital-ship default. qtFRED's Initial Status dialog also counted every flagged ship as scannable. Both now follow the game's rule. | [1eadc12](https://github.com/ofp-fs2open/fs2open.github.com/commit/1eadc12496106747802dc53e09db99b2ba77ddad) |
| **QtFRED list and dropdown type-ahead stopped cycling** | Tapping a letter in a list or dropdown jumps to the next item starting with it, but tapping it quickly stopped moving: Qt searched for the repeated letters ("ff") instead of the next F. It now keeps cycling however fast the letter is tapped. | [b8da690](https://github.com/ofp-fs2open/fs2open.github.com/commit/b8da6902a9cd98bf1824c07811151faa76139d14) |
| **QtFRED ship arrival distance limited to two digits** | The Ship Editor's arrival distance field only accepted 0 to 99, so a ship could get stuck at its target's minimum distance (for example 39) with no way to type a larger value. It now takes any distance from the target's minimum up, like the Wing Editor, and raises the distance to the new minimum when the arrival location changes. | [5fbe775](https://github.com/ofp-fs2open/fs2open.github.com/commit/5fbe775345030611e04a679267a9cf9df1fdbee6), [ddbe824](https://github.com/ofp-fs2open/fs2open.github.com/commit/ddbe8245317bf8be4f3eca3e065e5399a8463537) |
| **QtFRED help pages missing from the built help** | The Custom Data concept page was linked from other help pages but never registered, so those links went nowhere; a stale duplicate help project file that the build never used was removed. | [5fa3b9d](https://github.com/ofp-fs2open/fs2open.github.com/commit/5fa3b9d0e72c9a78cb1fc463c8a54d0a679d18b2) |
| **QtFRED wing arrival distance reset to 0** | Choosing a wing's arrival target in the Wing Editor reset its arrival distance to 0 whenever it was above the target's minimum, while the box still showed the old value, so saving failed with "Arrival distance for wing ... must be greater than 0". The distance is now kept, and only raised to the target's minimum if it is too close. | [936bea8](https://github.com/ofp-fs2open/fs2open.github.com/commit/936bea8e39f99d2be655ccbd5e1e7eb297fd7719) |
| **QtFRED duplicate wing names** | Form Wing never checked the name, so two wings could share one, and empty names or names already used by a ship, prop, waypoint path or jump node were accepted. The name is now checked before the wing is formed. | [a77bf98](https://github.com/ofp-fs2open/fs2open.github.com/commit/a77bf98e0f5d6e44cd9969e69dce28f8b86b4c6e) |
| **QtFRED Additional Ship Properties fields jumping around** | The destroy time, escort priority and kamikaze damage fields appeared and disappeared as their flags were toggled, shifting the layout and tab order. They now stay in place and are disabled until their flag is checked ([#57](https://github.com/ofp-fs2open/fs2open.github.com/issues/57)). | [bae47a2](https://github.com/ofp-fs2open/fs2open.github.com/commit/bae47a204ecae1fd4d08c2cb6cb85da0b725309f) |
| **QtFRED object labels offset from their objects** | Ship and object name labels were drawn away from the objects they belonged to, because the labels were projected with a different field of view than the one used to render the scene ([#55](https://github.com/ofp-fs2open/fs2open.github.com/issues/55)). FRED2 and QtFRED now share one editor FOV define. | [187efe3](https://github.com/ofp-fs2open/fs2open.github.com/commit/187efe34e9379027f2d2e49af6eed9302e84f8f4) |
| **QtFRED message name warnings while typing** | The Events editor checked a message name on every keystroke, so typing a name like "Helprin" was interrupted by a warning at "Help" (a built-in message). A clashing name is now outlined in red while typing, and the warning only appears if you leave the field that way ([#50](https://github.com/ofp-fs2open/fs2open.github.com/issues/50)). | [8c7e078](https://github.com/ofp-fs2open/fs2open.github.com/commit/8c7e078fb04c8c71dcdaca3a862b0b0998d820b3) |
| **QtFRED autosave recovery crash** | Accepting "An autosave file for this mission is newer" asserted ("We have full path, but no separator!?"). After a recovery, Save also wrote into the autosave folder instead of the mission file. The recovered mission now keeps its own file name and asks before replacing the original. | [62ef2ea](https://github.com/ofp-fs2open/fs2open.github.com/commit/62ef2ea4e81d65ce6503cead8c7b7fc3ad4f7572) |
| **QtFRED Space after New/Insert Event added another event** | The New and Insert Event buttons kept keyboard focus, so pressing Space inserted yet another event instead of editing the new event's name ([#45](https://github.com/ofp-fs2open/fs2open.github.com/issues/45)). | [46b1f2c](https://github.com/ofp-fs2open/fs2open.github.com/commit/46b1f2c202cb129251ccdb8affa84dceafadb303) |
